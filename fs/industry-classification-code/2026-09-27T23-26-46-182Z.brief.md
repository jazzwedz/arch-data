# Coding brief — Industry Classification Code

> Generated by Team Repository on 2026-09-27 from the Functional Specification "Industry Classification Code v2". One file, self-contained: everything an implementation agent needs is here. The FS is the source of truth for behaviour — where this brief and the FS disagree, the FS wins.

## 1. Mission

Build standardized NACL industry-classification coding into the Policy Core System (CORE) so that Underwriters and Back-office Users can search, select, and store a single official 6-digit economic-activity code per company/partner, replacing the existing free-text 'Type of Company' field on the Modify Company > Identity screen. This requires extending CORE with a new NACL field, mandatory-field validation, and review-prompt logic; reusing the existing API Gateway (for authenticated, region-aware, rate-limited routing) and Notification Service (for review prompts); and standing up three new components — the NACL Reference Data Store, the NACL Classification Search Service, and the NACL Portfolio Migration Job — to hold, search, and pre-populate the official classification list. The result must ensure exactly one current, plausible NACL code per partner, sourced from an authoritative national classification list, with no parallel or historical codes kept at partner level, and with existing-portfolio companies pre-populated from confirmed prior assignments.

## 4. Scope

**In scope**

- Policy Core System (CORE) — the "Modify Company" > "Identity" screen change, the NACL field, mandatory-field validation, and the review-prompt trigger (UC-01).
- API Gateway — routing of CORE's NACL search/autocomplete requests to the NACL Classification Search Service, under its existing authentication, rate-limit, and region rules (UC-01, RG-01 to RG-06).
- Notification Service — delivery of the NACL code review prompt (UC-01).
- NACL Reference Data Store — storage of the official NACL classification list and its hierarchy (UC-01).

- Changes to Commercial products themselves — explicitly excluded; the change applies only at the partner/company level.

Anything not listed above is out of scope.

**Constraints**

- The NACL code applies to all Commercial products in CORE V2 and V3.
- Requests carrying customer PII, including NACL search and selection requests, must be processed only in EU regions (RG-04).
- Every request to /api/policies/* endpoints, including NACL search requests routed through CORE, must come from an authenticated session (RG-02).
- Exactly one NACL code is permitted per partner; the partner record must not carry parallel or outdated codes.

## 5. Work items — use cases

### UC-01 — NACL Code Selection and Maintenance

**Actors / components:** Underwriter / Back-office User, Policy Core System (CORE), API Gateway, NACL Classification Search Service, NACL Reference Data Store, NACL Portfolio Migration Job, Notification Service

**Flow to implement:**
1. Underwriter / Back-office User → Policy Core System (CORE) (sync): Open Modify Company > Identity screen, create/update company
2. Policy Core System (CORE) → API Gateway (sync): Search NACL by keyword or code
3. API Gateway — Forward search request
4. Underwriter / Back-office User → Policy Core System (CORE) (sync): Select 6-digit code from results
5. Policy Core System (CORE) — Validate mandatory field and store code on company master data
6. Policy Core System (CORE) → Notification Service (async): Prompt review if code is stale/missing on future updates

**Rules to implement:** RG-01 (Auto-route by policy version), RG-02 (No anonymous policy access), RG-03 (Per-tier rate limit), RG-04 (PII data residency), RG-05 (Request priority score), RG-06 (Throttle policy-holders under fraud review)

**Implementation notes:** In CORE, replace the 'Type of Company' field on Modify Company > Identity with a NACL search-and-select control: a keyword/code search bar with autocomplete, a results table showing the 6-digit code and description, single-click selection, and read-only display of the full hierarchy (section/division/group/class/category) for orientation only — only the 6-digit code is stored (RG-08, RG-09). CORE's search calls go through the existing API Gateway, which must apply RG-01 (v2 routing by policy date), RG-02 (reject unauthenticated requests), RG-03 (tenant rate limiting), RG-04 (EU-only processing since these are PII-bearing requests), and RG-05/RG-06 (overload prioritization / fraud-review throttling on claims paths) before forwarding to the new NACL Classification Search Service, which reads matches with hierarchy from the new NACL Reference Data Store. CORE must enforce RG-07: the NACL Code is mandatory on company creation, on master data changes where activities changed, and on contract changes, showing nacl.mandatory.error and blocking save if empty; on later master data/contract/renewal changes CORE must check plausibility per RG-11 and, if the code is stale or missing, call the Notification Service asynchronously to deliver nacl.review.prompt (do not block the update). The NACL Portfolio Migration Job runs once, reading only confirmed codes from the NACL Reference Data Store and writing them into CORE as initial pre-population for existing-portfolio companies (RG-10); codes not marked confirmed, or not yet available, must be left for the user to complete via the mandatory-field flow. Edge cases to handle: no search results found, partial vs full code search, attempted selection of a non-6-digit hierarchy node (must be disallowed), save attempts with an empty field on the three mandatory triggers (RG-07), and updates that would otherwise create a second/parallel code for the same partner (must overwrite in place per RG-09, never store a second value).

## 11. Suggested order of work

1. 1. Data model changes in CORE (UC-01, RG-08, RG-09, §7 Data Requirements): add the mandatory NACL Code field (6-digit numeric) and a derived, non-mandatory NACL Description display field to the company/partner master data record; remove/retire the 'Type of Company' field; ensure the schema enforces a single current code per partner with no parallel/historical values.
